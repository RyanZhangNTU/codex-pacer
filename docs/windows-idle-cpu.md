# Windows 空闲 CPU

2026-11-03，Windows 11 x64 build 26200，16 逻辑核，150% 缩放，Release。本机五分钟样本中，修复后的 Black 与 Glass 外壳均达到收起单核不超过 1%、展开不超过 2%、隐藏或受控遮挡不超过 0.5% 的目标。下面保留首次未达标的遮挡结果和被夹具校验拒收的记录。

本次改动限于 Windows 外壳、原生装饰和 EngineSupport。额度刷新、发现间隔、账户与源切换的业务规则保持原样；Mac 与共享 Core 没有改动。

## 唤醒来源与处理

| 来源 | 处理 |
| --- | --- |
| WPF 徽标永久旋转，持续提交分层窗口 | 将外环交给 Windows.UI.Composition，保留 1.8 秒周期。WPF 保留中心内容、输入、辅助功能及有限提示动画。小型装饰 HWND 不激活、不接收输入，只在数据、布局、DPI 或透明度变化时同步。 |
| 额度轮换的永久关键帧时钟，静止段仍有调度 | 改成下一次切换期限的单次计时器，保留四秒槽位和 350 ms 线性淡化。迟到唤醒直接进入当前相位，不补跑旧槽位；相同值不重建文字层或重启周期。 |
| 已移除属性动画的根时钟，等待 GC 才停止 | 有限的波纹、缩放、页切换、悬停和淡化持有可控制时钟，在完成、替换或卸载时显式停止并移除。生产代码不强制 GC。 |
| 岛被不透明全屏窗口遮住时，WPF 可见性仍为真 | 用 WinEvent 合并检查层级、位置、显示与虚拟桌面变化，确认完全遮挡后暂停徽标和额度轮换。恢复时重新显示原值。没有新增轮询，也不改变岛层级、逻辑展开状态或业务刷新。 |
| 不变状态仍通过 IPC 发布 | Windows 输出端比较完整编码状态，只忽略序号、捕获时间和紧凑查询的参考时间。任务时间、额度时间、价格钟、账户上下文和动作引用等变化仍发布。通知事件与显式 demo 额度重试的快照确认保留；序号只在实际发布时推进，每次初始化都发布完整首帧。 |

徽标的纹理来自原有外环绘制，颜色变化时保留有限过渡。合成器不可用时保留 30 fps 的 WPF 旋转回退，只在显示或合成器通知后重试。原生装饰更新位置时保持在内容窗口附近，不把自己提升到其他遮挡窗口上方。

## 定位证据

WPR 的 CPU 采样被系统策略拒绝，错误码为 `0xc5585011`。没有提权或修改策略，结束后确认无遗留 WPR 录制。随后使用 [dotnet-trace](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/dotnet-trace) 的 `dotnet-sampled-thread-time,dotnet-common`、WPF Render 优先级调度计数、属性时钟检查和逐项停用对照。

栈中出现 `MediaContext.Render`、`CommitChannel`、几何计算以及等待与管道读取。线程采样包含墙钟等待时间，不能把等待比例当作 CPU 占比。诊断用短样本中，停用徽标后进程单核占用从约 8.23% 降到约 1.04%；停用徽标与额度动画后，测试专用 GC 又让遗留 Render 调度归零。这些短样本采集时有其他测试负载，仅用于定位，不用于验收。生产修复通过时钟所有权释放资源。

原始 trace、完整合成快照和拒收样本留在本地忽略目录。仓库只保留这份说明和[数值记录及构建哈希](performance/windows-idle-cpu.json)，不提交新增截图、进程号、账户、任务正文或本机来源路径。

## 五分钟对照

每格为“单核百分比 / 整机百分比”。进程 CPU 除以墙钟时间得到单核值，再除以 16 得到整机份额；它不包含 DWM 或 GPU。

| 外壳状态 | 改前 Black | 改后 Black | 改后 Glass | 单核目标 |
| --- | ---: | ---: | ---: | ---: |
| 收起，数据不变 | 9.839 / 0.6149 | 0.344 / 0.0215 | 0.375 / 0.0234 | ≤ 1 |
| 展开，数据不变 | 10.240 / 0.6400 | 0.292 / 0.0182 | 0.307 / 0.0192 | ≤ 2 |
| 隐藏 | 1.109 / 0.0693 | 0.047 / 0.0029 | 0.115 / 0.0072 | ≤ 0.5 |
| 全屏不透明遮挡 | 2.359 / 0.1475 | 0.083 / 0.0052 | 0.125 / 0.0078 | ≤ 0.5 |

每个样本按 300 秒采集，原始时长均在 300 秒的 0.01 秒以内，使用相同的固定合成快照及 notch 模式，测量期间不注入变化。第一次独占时段同时运行改前 Black、改后 Black、改后 Glass，三个位置互不重叠；该阶段收起、展开和隐藏已达标，但遮挡分别为 0.891% 和 0.792%，没有达到目标。随后加入遮挡暂停，最终独占时段用 owned 遮罩同时重测 Black 与 Glass 各五分钟，得到表中最后一行。前三态来自遮挡暂停修复前，最后一行包含该修复；数值记录保留各阶段的源码和二进制哈希。

对照以 `61cfb03` 为基线。采样后，本修复无冲突重放到 develop 的 `af196e1`，并重新构建和运行引擎、Desktop 回归。该次上游更新包含 Claude runtime 改动；上述五分钟数据没有重测这部分上游差异。

收起与展开的 WPF Render 调度从每五分钟约 43,000 次降到约 1,380 次，剩余工作对应额度淡化。隐藏与最终遮挡均为零；所有固定输入样本的根窗口帧应用计数为零。最终遮挡样本中，整机忙碌率约 5.28%，两个外壳各收到五个后台快照，但固定显示未重新注入。

| 引擎状态 | 改前单核 / 整机 | 改后单核 / 整机 | 快照数，前 / 后 |
| --- | ---: | ---: | ---: |
| 空来源，无运行任务 | 0.109 / 0.007 | 0.161 / 0.010 | 86 / 86 |
| 只读真实来源，有流式任务 | 2.500 / 0.156 | 3.708 / 0.232 | 218 / 263 |

引擎也各测五分钟。空来源样本达到单核不超过 1% 的目标，保留价格钟和额度时间等有效变化。有流式任务的两组均有两个运行任务，但含新输出的快照分别为 131 和 155，负载不同，不能据此宣称引擎性能改善或完成等负载回归比较。完整状态比较本身也有编码成本。四组均无协议错误或 stderr，关停有确认，耗时不超过 0.009 秒。真实来源只读，不截图、不记录协议正文，也不发起源配置修改。

## 遮挡夹具与全屏策略

暂停修复后的首次五分钟复测，被结束时的全部表面层级校验拒绝，两组都没有作为 CPU 结果采用。独立 Topmost 遮罩与岛处于同一层级，不能提供持续遮挡的系统约束；后续短测没有复现具体的抬升操作，因此没有把某个产品 API 定为原因。

最终夹具使用 owned 不透明遮罩构造受控遮挡，仍核对内容、背景和两个徽标表面。校验没有放宽。owned 窗口的层级约束见 [Windows window features](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#owned-windows)。该夹具的遮挡与恢复回归通过，两个最终五分钟样本也通过开始和结束时的层级校验；测试结束后窗口和引擎全部退出。

Mac 的 `showInFullscreen` 开启时使用全屏辅助窗口，关闭时不加入全屏空间。Windows 对应的 `fullscreen-policy` 仍为 `pending`。本次只在岛确实被覆盖时暂停装饰，不实现全屏开关、不调整产品层级，也不代替真实全屏应用的显示策略验收。

## 回归检查

- `QuotaScheduleChecks` 覆盖两家、三家、完整周期、淡化边界、迟到、单家与非法时间；原有 121 个共享动画采样仍通过。
- `IdleSchedulingChecks` 在实际 WPF 窗口上检查静止段零 Render 回调、周期结束释放时钟、隐藏后停止计时、相同值不上传外环纹理，以及设备失败后的回退和通知恢复。检查不依赖 GC。
- `OcclusionPolicyChecks` 与 `OcclusionSchedulingChecks` 检查保守遮挡条件、实际暂停与恢复、零空闲 Render/计时唤醒，以及逻辑展开状态和引擎序号保持不变。
- `EngineSnapshotEmissionTests` 覆盖 100 次不变状态、投影变化、通知重复事件、动作序号、显式重试确认和重复初始化。原有回归断言保留。
- 更新到 `af196e1` 后，Release 构建无编译警告；完整 Windows 引擎/portable 回归 679 项通过，Desktop 集成 23 项通过，139 个 Core 文件独立编译通过。合同检查六项、Python 语法及 `git diff --check` 通过。SwiftPM 仍有现有的 native build-system 弃用和便利符号链接提示，不属于编译器诊断。
- 原有轮廓像素检查的 21 个合成场景均无轮廓外像素变化。

完整展示矩阵曾为配合主线测试而中途停止；已完成受影响的中英文岛窗口、导航、Harness、Black/单服务额度，以及动画和减少动态效果用例。没有将这次中止记录为完整矩阵通过，CI 继续运行原有完整检查。

可以在独立屏幕时段使用 `scripts/windows/check-shell-idle.py` 重测。先构建 `windows/Tests/BackdropTests/Pacer.BackdropTests.csproj` 的 Release 版本，再传入 `--probe`、新的 `--output`、`--seconds 300`、`--appearance classic|liquidGlass` 和相同的合成 `--snapshot`；`--states` 可选 `collapsed expanded hidden covered`。引擎使用 `scripts/windows/check-engine-idle.py`。长测只在开始和结束读取进程 CPU，测量中不轮询 CPU。

## 限制与待检查项

透明分层窗口及 `WS_EX_NOREDIRECTIONBITMAP` 独立合成窗口保守不判为完全遮挡。WPF 回退仍需客户端绘制，本机硬件合成的 CPU 数字不适用于回退状态。设备故障与恢复有自动回归，回退状态没有五分钟 CPU 验收。

结果仅覆盖一台设备、150% 缩放和上述受控状态。DWM/GPU 开销、其他显卡、远程桌面、电源模式及真实全屏应用仍需后续验收。有效的数据、到期和业务刷新继续唤醒；没有停用这些计时来取得空闲数字。

待 Mac 实机检查：无。本次未修改 Mac 或共享 Core。
