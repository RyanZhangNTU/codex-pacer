# Claude integration design comparison

Reviewed on 10 October 2026 for the 3.0.0 development candidate. This records the source patterns considered, the choices implemented in Pacer and the evidence boundaries. It separates locally verified candidate behavior from publication and authentication scenarios that were not exercised. Runtime definitions remain in [development and data semantics](development.md); packaging and applicable manual checks remain in [the release workflow](releasing.md#validation-scope).

Integration scope: Claude local/SSH support and the unified quota interface build on the Codex Remote Control support from [PR #77](https://github.com/RyanZhangNTU/codex-pacer/pull/77).

GitHub references below are pinned to reviewed commits. Vendor documentation is the canonical primary source as read on the review date and can change. “Adopt” means adapting a design principle to Pacer's existing native runtime, not adding the referenced application as a dependency or copying its implementation. Stars are not a correctness or energy measurement.

| TTFT and TPS | Official [numeric request spans](https://code.claude.com/docs/en/monitoring-usage#span-attributes) distinguish request duration, TTFT, first-content timing and output tokens. [MessageDisplay](https://code.claude.com/docs/en/hooks#messagedisplay) has partial interactive delivery and final-only noninteractive delivery. | Matching successful OTLP evidence supplies request timing and authoritative output-token accounting. A complete observed response window with authoritative deduplicated tokens can provide an estimated rate after a verified stop; confirmed required-tool waits are excluded. A genuine partial first display or numeric TTFT can supply latency, with provider-specific help. Authoritative same-request timing outranks an observed estimate. | Full-message completion time cannot infer first output. Missing numeric evidence in Desktop SDK or `-p` final-only paths remains unavailable. No decoder-speed or tokenizer-normalized benchmark claim; summed available provider TPS retains each provider's measurement definition and timestamp. | [ClaudeActivityTelemetryTests](../native/Tests/PacerCoreTests/ClaudeActivityTelemetryTests.swift), [ClaudeObservedRequestTests](../native/Tests/PacerCoreTests/ClaudeObservedRequestTests.swift) and [ProviderTests](../native/Tests/PacerCoreTests/ProviderTests.swift) cover unsafe/missing spans, tool boundaries, duplicate accounting, partial/final displays and precedence. | Subagents and completion reminders | Official [SubagentStop](https://code.claude.com/docs/en/hooks#subagentstop) and [span correlation fields](https://code.claude.com/docs/en/monitoring-usage#span-attributes) provide agent/parent ownership. CUT's event reducer is a useful separation of ingestion and presentation, not a completion-retention specification. | Provider-qualified host/session identities group children only under the matching parent. Typed foreground Agent results and strictly validated background engine notifications correlate only to observed child/task/tool ownership; an internal agent without observed work is not counted as active. Available child throughput contributes to the shared task total. Matching late numeric data can enrich a retained card without another notice, extending retention or reviving a dismissed turn. Verified conversation opens persist bounded SHA-256 acknowledgment hashes scoped to provider, home, host, session, turn and ending state. A parent open acknowledges only the captured ended descendants whose identities, source and observed ancestor chain remain unchanged after navigation. Opaque source and ending tokens reject an asynchronous open after source rebinding. | No grouping by bare session ID across hosts/providers, guessed parent from display name, human text treated as an engine notification, historical notification replay or dismissal merely because metadata disappeared. Running children, late endings, new turns and changed relationships are not swept into a parent acknowledgment. Failed opens, Terminal handoffs and source removal do not persist acknowledgments. The store contains no raw path, account identity or task text. | [ClaudeSubagentLifecycleTests](../native/Tests/PacerCoreTests/ClaudeSubagentLifecycleTests.swift), [ProviderTests](../native/Tests/PacerCoreTests/ProviderTests.swift), [CompletionInboxTests](../native/Tests/PacerCoreTests/CompletionInboxTests.swift) and [ProviderDisplayTests](../native/Tests/PacerIslandTests/ProviderDisplayTests.swift) cover typed foreground/background projection, isolated grouping, historical baselines and selective disable. ## Validation record

Candidate-specific results (test runs, build identifiers, native UI walkthroughs, live-source observations and process samples) belong in the commit or pull request that introduced a change, with detailed manifests kept under ignored `output/validation` and `output/performance`. They are not maintained here. Observed throughput is response throughput, not model-side decoder speed, and short process samples do not establish whole-machine or battery power. Authorized packaging, installation and publication follow the [release workflow](releasing.md).
