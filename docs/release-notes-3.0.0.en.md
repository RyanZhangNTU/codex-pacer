Codex Pacer 3.0.0 build 48 is a development candidate for Codex and Claude Code. Tasks share the top of the expanded island with provider colors. Paired rings show both providers' remaining quota with a pace tick and ahead/on-pace/fast verdict, the other period one line below, and tiny 5h/7d controls; a single provider's ring layout shows both periods, and confirmed weekly-only limits use a PRO placeholder. When only Codex is enabled and its primary account reports limits without a 5h window, the original quota bars show all actual windows, including nonstandard or unspecified durations. History charts and full quota details stay in Settings. Thin ring strokes surround the central quota value and compact reset countdown; normal source/update details move to hover help and Settings, while stale/error states remain visible. The collapsed island merges status and task count into one animated activity badge beside available TPS, with quota percentages distinguished only by provider color. Successfully opened completion cards stay dismissed across normal relaunch. Claude tasks show request speed and first-output time from current Claude Code telemetry, and Pacer's hooks start faster without delaying streamed text. The interface uses one status icon family, two-line task rows with right-aligned speed and first-output metrics, and a sidebar Settings window.

Settings can enable either module independently. Automatic defaults detect installed apps and CLIs; explicit choices persist. Claude supports local sources and configured SSH aliases. Verified Desktop SSH/WSL transcript copies are excluded from the default local source, and source-status delivery stays immediate through bounded SSH transport. Optional monitoring setup adds hooks and numeric telemetry while preserving existing settings. Matching OTLP request evidence supplies exact numeric request timing; verified-stop transcript windows can supply estimated throughput. First-output timing requires an explicitly turn-owned partial display callback or reported TTFT; Desktop SDK/`-p` final-only messages do not supply it. Claude opens through verified Desktop mappings or a real Terminal resume session; only a successful verified Desktop open clears its completion card.

Codex Remote Control joins local and SSH tasks through the connected Desktop owner's stream, with a separate switch under Codex sources. Codex must stay open and connected, and the conversation must be loaded by a stream owner; Pacer adds no independent remote-host discovery or log fallback. Cached counters do not establish a new measurement or unseen first-output latency. The inherited mid-request TPS fallback remains approximate and can still produce inflated values. See [upstream PR #77](https://github.com/RyanZhangNTU/codex-pacer/pull/77) and the [source and accounting limits](development.md#codex-accounting-and-lifecycle).

Claude quota prefers a fresh matching status-line sample or Pacer's independent WebKit session. Sign in to Claude opens a dedicated website window for you to sign in and complete verification; multiple organizations require an explicit selection. Production never reads another application's Keychain or Safe Storage. Cookies remain WebKit-managed. Quiet Pacer-owned OAuth cache/environment/file sources are compatibility fallbacks. Expired web sessions require sign-in again; missing reset dates and unsupported Credit/banked-reset fields remain unavailable.

For macOS 14 or later, with universal build support for Apple Silicon and Intel. This note does not establish publication, installation or completed manual acceptance.

For a manual candidate installation, quit the old app and drag Codex Pacer from the DMG into Applications. If an unsigned candidate is blocked, use System Settings → Privacy & Security → Security → Open Anyway, then reopen the installer or app. Packaging and publication follow the [release workflow](releasing.md).
