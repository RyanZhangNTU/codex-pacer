# Development and data semantics

## Structure

- `native/Sources/PacerCore`: quota decoding, task lifecycle, rate estimates, source discovery, transport, completion retention and window geometry.
- `AgentProvider` / `ProviderModules`: provider identity, bounded installation detection and automatic or explicit module choices. Claude collection/quota adapters feed the shared activity, performance and completion model.
- `native/Sources/PacerIsland`: SwiftUI/AppKit presentation, settings, notifications and native glass.
- `native/Tests/PacerCoreTests`: regression coverage for lifecycle, privacy, transport, rate calculation, account isolation, retention, geometry, singleton locking and preferences migration.
- `native/Tests/PacerIslandTests`: asynchronous conversation-opening coverage, including failed launches, repeated clicks and newer completion/notice races.
- `scripts/native`: isolated local build/test entry points.
- `scripts/performance/benchmark-events.py`: controlled Desktop IPC event replay; see [performance checks](#performance-checks).
- `scripts/release`: native signing, notarization and publication.
- `marketing`: editable Chinese campaign source and reproducible exports.

Use Xcode 26 or newer. Run affected suites with `make test TEST_FILTER='SuiteName|OtherSuite'` during development and one full `make test` for a release candidate. `make build` creates an app for UI checks; a release build already performs compilation and packaging. Sources and build outputs are isolated in `/private/tmp`; pinned dependencies and compiler modules reuse a per-user cache there. Resolution follows `Package.resolved` without refreshing unchanged dependencies. The executable remains `CodexPacerIsland`; the user-facing app is Codex Pacer. `native/Info.plist` is the production version source.

Development builds are ad hoc signed. The build prints its app path; open that app in Finder for UI checks. Exit the installed app first: all copies share the same singleton lock. Demo arguments `--demo` and `--demo-completion` supply labeled sample data (`--demo --demo-subagents` supplies one parent and three synthetic agents) without querying Codex. `--demo-notch` supplies hardware-notch geometry for marketing on virtual displays; production mode uses the screen’s own safe areas. Command+1/2/3/4 switches synthetic thinking/tool/reply/completion events through the same runtime projection. Demo clicks open an explicitly labeled sample destination, never a real conversation. `--expanded` starts with the island open. Command-line diagnostics `--diagnose` and `--diagnose-events --observe-seconds 20` report protocol/counter availability without credentials, account identity or task text. Add `--desktop-only` to verify local runtime and Desktop attention/discovery without starting SSH helpers.

Applicable manual checks, updater isolation and publication are defined in the [release workflow](releasing.md#validation-scope).

## Data and calculation

Codex quota comes from a dedicated read-only app-server connection using `account/read` and `account/rateLimits/read`. No turns are created or resumed. Missing data remains unavailable. Multiple service buckets take precedence over a legacy single-bucket response. Credit and reset details are read from the service, without API-price conversions.

### Provider ownership and Claude sources

The reviewed upstream patterns, implementation choices and acceptance limits are recorded in the [Claude integration design comparison](claude-integration-design.md).

`AgentProvider` distinguishes Codex and Claude. Existing Codex activity keys stay `host:UUID`; Claude keys are `claude:host:session`. Parent/agent grouping cannot cross provider or host. Claude agent IDs may be bounded opaque identifiers rather than UUIDs. Display metadata, late numeric updates, input/approval requests and retained completions use the same provider-qualified identity. Turning one module off releases only its collectors, work and reminder baselines, preserving the other module's tasks and completion cards.

`ProviderModules` stores automatic, enabled or disabled choices. Absent/malformed settings default to automatic, which detects known application and executable locations without launching a provider or inspecting authentication. Explicit choices override later detection; restoring automatic does not freeze the detected value in preferences. Existing Codex display, quota-window and cache choices remain intact. Claude has its own quota-window selection and history directory. The shared singleton lock and production bundle identity remain unchanged.

The expanded task region contains both enabled providers regardless of the dashboard quota period. Two side-by-side nested rings show each provider in the shared 5h/7d period; a single provider's ring layout shows its 5h and 7d slots together. When only Codex is enabled, its primary `codex` bucket has no 300-minute window and at least one reported quota value, positive duration or reset date, the previous quota bars render all actual snapshot buckets/windows, including nonstandard and unspecified durations. Missing, empty or wholly unmeasured snapshots do not establish this exception or a weekly-only account. Source and freshness remain available in Settings and hover help; stale indicators and errors remain visible, and stale/error bars have no live pace. Outer rings encode remaining quota and inner rings encode remaining time from the actual duration and reset date. Missing values remain unknown independently. Tiny footer period controls are separate from the existing collapsed-window choices. Where the ring layout applies, a weekly-only PRO placeholder requires fresh valid weekly quota/reset evidence in the primary account bucket, no five-hour/unknown-duration window and no quota error; model-scoped limits and wholly unavailable snapshots cannot imply PRO. Codex-only accounts without a five-hour limit use bars instead of a PRO ring. The marker describes a layout state, not a detected paid plan. History charts and full quota/Credit/reset details stay in Settings with independent provider source, freshness and warning states. Expanded provider names identify Codex and Claude. Rings use thin quota/time strokes with a central quota value and compact reset countdown; source, full reset dates, bucket names and update age are available on hover and in Settings. The collapsed bar combines task counts, available measured TPS and attention, but does not add or average independent quota percentages. Compact quota/time values use provider color without visible names, abbreviations or marker dots; full provider names remain in accessibility/help text. One service's quota failure cannot replace the other service's data or error state. Source reset cancels old quota work and rechecks generation after every suspended read; changing the Codex directory resets Claude only when enabled SSH discovery actually uses that directory.

Production quota reads prefer a fresh status-line sample with a matching hashed account scope, then `ClaudeWebQuotaClient` using a session from Pacer's dedicated `WKWebsiteDataStore`. Connect opens Pacer's own claude.ai WebKit login window; the user completes ordinary website sign-in and any challenge. Production performs zero reads of another application's Keychain/Safe Storage, including during Connect, and imports no Claude/Safari/Chrome cookies. Session cookies are managed only by WebKit; quota requests receive them transiently in memory without writing a parallel JSON/cookie store or logging values.

The Web adapter issues read-only GETs for account, organization and usage data. It verifies session/account/home/organization binding and rejects redirects, mismatched authentication and HTML challenge responses instead of treating them as quota. A known selected organization must belong to the authenticated account; multiple organizations require explicit selection rather than choosing the first result. Session/account/organization changes invalidate cached identity and in-flight results. Expiry or a website challenge requires a user-visible sign-in/verification action; startup and refresh never open that window automatically. Network failures and 429 responses remain retry states. Valid `Retry-After` backoff is bounded and scoped to the matching session/binding; retained quota keeps its original capture timestamp.

Without an established WebKit session, `ClaudeQuotaClient` remains a quiet compatibility fallback for Pacer-owned OAuth cache entries or explicitly supplied environment/file credentials. The own-cache item uses its default creator ACL, without relaxation or synchronization; no production fallback reads a foreign Keychain item. This is not a Data Protection Keychain entitlement workaround or the primary connection/import flow. A usable existing token remains account/home/organization bound, and its expiry/revocation does not trigger an automatic authorization dialog. OAuth compatibility requests keep verified-provider preference and account/token-scoped bounded Retry-After behavior.

Normal relaunch may reuse a still-valid WebKit session; this does not establish indefinite website access or persistence across every binary/signing/profile change. Both quota integrations are private and version sensitive. Settings, errors and logs contain no cookie, OAuth token, raw response or account identity. Desktop history is not an automatic quota fallback. Missing resets disable pacing/current-cycle recording; missing Credit balances and reset-bank data remain unavailable.

Claude task collection uses a bounded native incremental reader, optional additive hooks and a loopback-only OTLP HTTP/JSON receiver. Transcript text is reduced to presence/kind markers before activity projection; prompts, response content, tool arguments/output and account attributes are not retained. Hooks supply start, tool and attention boundaries. Stop/SubagentStop observers only record an attempted stop. An explicit transcript `stop_hook_summary` completes a turn only with `preventedContinuation == false`, explicitly empty `hookErrors` and `hookAdditionalContext` arrays, and ownership established by the prompt/parent-UUID chain. The boolean alone is insufficient; missing ownership after a gap never falls back to a timing guess. This prevents another Stop hook's continuation from retiring the current turn prematurely. A foreground Agent's typed completed result can end only its observed owned child. An asynchronous launch stays active until an engine-authored background notification proves a terminal status for the exact stored child/tool pair. Only the reserved direct header is projected, under the engine origin gate; summary/report text is opaque and never retained. Child ownership stays bound to its own observed run even after the parent starts another prompt. Unstarted internal-agent hook events do not create public tasks. Explicit engine interruption markers are accepted only for the matching active owned prompt without human-message provenance, with the typed-prompt marker preventing spoofing; only marker presence is retained. Missing files/gaps leave activity unconfirmed without inventing interruption. Initial log/spool baselines retain historical cards without replaying completion reminders, including boundaries split across publications.

Claude Desktop can copy SSH/WSL transcripts into the default local Claude home. A unique validated SSH/WSL context in the active Desktop account's bounded metadata excludes that copied session and its children before bounded file selection, so mirrors cannot occupy real local reader slots or directory watches. It also removes the erroneous Local completion card and displayed notice. Custom Claude homes retain their own local observations. Ambiguous or missing metadata leaves source ownership unchanged; provider/host-qualified activities remain independent even when their session UUIDs match. Exclusion metadata is refreshed during discovery and cached for ordinary publications.

Both local and SSH transcript readers drain ordinary appends sequentially in bounded chunks. The 512 KiB initial and 128 KiB append budgets are per-read limits, not evidence of lost data. Remaining complete records/backlog schedule another drain and preserve the parent-ID chain through large Desktop attachment bursts. A real over-budget attachment/gap still invalidates ownership and leaves terminal state unconfirmed. Historical-baseline publication waits for its bounded drain to finish; this implementation does not itself establish acceptance of every Desktop burst in a packaged app.

The native Claude reader checks cursor existence, inode, size and readability before opening a file. An unchanged readable EOF cursor skips open/seek/empty-read work; buffered complete records, new bytes, replacement and disappearance still use the normal bounded path. Task grouping in the UI model is reused only while its activity snapshot is unchanged. Overview calculations reuse those groups with the exact current Date, so the freshness boundary, retained TPS and lifecycle projection keep their existing precision. These changes reduce repeated work without changing collection cadence or asserting a measured whole-app energy reduction.

Native transcript context and activity projection share one bounded JSON document per line; only sanitized fields and identifiers survive that line. Selected project/subagent directory watches remain attached between ordinary reads, allowing new files to trigger discovery immediately. Claude's watcher bounds are 32 files plus 99 parked directory descriptors; Codex retains its existing four-directory bound. The SSH helper likewise decodes each transcript line once. Known-file inotify appends mark that cursor dirty without a project-tree scan; create/delete/move, self events and overflow still reconcile the bounded inventory. None of these paths adds a polling timer or changes first-output/lifecycle timing.

Matching numeric OTLP `llm_request` evidence supplies exact request duration, output-token accounting and reported TTFT. An observed fallback pairs unique authoritative transcript request/message counts with a complete prompt/tool-result-to-model-output window, excludes confirmed tool waits and settles only after a verified owned stop. It is marked `observedRequest` and remains an estimate; a same-request OTLP sample outranks it regardless of delivery time. An actual interactive MessageDisplay callback with validated turn/message IDs, `final == false`, `index == 0` and nonempty-text presence may establish client-observed first-output timing. Desktop SDK, `-p` and other final-only delivery paths cannot establish that proxy; absent numeric TTFT it remains unavailable. Neither full transcript text nor display delta content is retained. Numeric measurements may enrich only the matching observed turn and do not create a task, replay a reminder or extend completion retention.

Structurally ineligible MessageDisplay callbacks return before acquiring the hook-state lock or rewriting state/spool files. An eligible first partial callback still resolves a missing legacy prompt ID from the owned thread's state and preserves child/parent routing. Duplicate, previous-prompt and post-completion callbacks cannot move first-output timing or reopen a completed turn. Hook identifiers reject trailing newlines as well as other characters outside the bounded identifier grammar.

Local and SSH OTLP receivers accept HTTP/JSON with identity or gzip encoding, each bounded to 1 MiB compressed and expanded. Truncation, CRC failure, trailing data and expansion overflow fail without publishing frames. Typed AnyValue fields remain distinct; integer tokens and nanoseconds are normalized exactly from bounded decimal/exponent forms before range checks, so fractions, booleans and nonfinite values cannot become token counts. Invalid explicit span values shadow resource defaults; a present invalid primary request/model key cannot borrow its alias. These checks preserve correlation and do not establish a successful turn ending.

Claude's explicit Settings setup adds Pacer command hooks, installs a status-line wrapper that passes the original stdin/output through to an existing renderer, and stores sanitized quota/lifecycle records beneath the selected Claude home's `pacer` directory. It adds beta OTLP trace settings for `127.0.0.1:4319` only when existing tracing settings/headers do not conflict. Conflicting telemetry is preserved and setup reports partial configuration. New Claude Code sessions must load the changed settings. Local project-directory metadata may be retained for navigation; it does not leave the host. A direct Desktop continuation URL requires a verified `local_UUID` mapping from the active Desktop account; SSH mappings additionally match the canonical host/user/port route. Default Desktop metadata cannot establish ownership of a separately selected local Claude profile. An observed Claude child can route through a validated parent UUID or a bounded, observed same-provider/host/source ancestor chain to a UUID root, even when the parent card is absent. The same Desktop metadata or profile/SSH resume checks still apply; the child's directory or Desktop ID never establishes the ancestor's path or continuation URL. Without a verified mapping, local UUID sessions open a real Terminal TTY with an explicitly quoted `CLAUDE_CONFIG_DIR` for the selected home. The installed CLI uses `--desktop --resume` only for the default profile with Desktop present, and `--resume` for custom profiles or CLI-only use. SSH fallback opens a validated SSH TTY resume command. Opening supplies no prompt and does not create a turn. The actual open outcome determines acknowledgment: successful verified conversation handoff dismisses the matching captured ending and any eligible captured terminal descendants described below; Terminal dispatch or failure preserves them because launch success alone does not confirm that the conversation opened. A queued open from a replaced source is discarded before dispatch.

Claude SSH targets reuse enabled discovered Codex aliases and accept additional validated aliases for Claude-only installations. They use existing SSH authentication and known host keys. Owned Python 3.6+ helpers sanitize data on the host, retain separate provider state, and exit on owner stdin EOF or broken stdout. The remote helper is read-only; users configure hooks/telemetry on each remote host separately. Local setup does not establish that remote configuration is present. Per-provider status and unavailable-source reporting remain independent.

Claude SSH pipe delivery uses `PipeChunkReader` readiness callbacks and a bounded `AsyncStream`, rearmed after actor consumption to retain ordered backpressure. Within each bounded read, the owned hook spool is ordered before transcript cursors during cold replay and simultaneous dirty appends, matching the native reader's ordering. Prompt ownership can therefore precede engine continuation and clean-stop records instead of a later hook start reviving an ended turn. Exact prompt/parent links and explicit terminal evidence remain required; ordering adds no silence or timeout heuristic. A quiet pipe does not occupy a Swift cooperative worker while waiting for data. Source-status frames publish immediately; ordinary numeric updates retain visibility-based batching. EOF, cancellation and reconnect release only the owned reader/helper, preserving the other provider's transport.

### Codex accounting and lifecycle

Click the available-reset count to expand or hide expiry details inside the island. Available credits are deduplicated, grouped by exact expiry and sorted earliest first, including deadlines beyond the displayed weekly curve. Dates include seconds and use the local time zone, named below the list. Expired and redeemed credits are excluded; missing detail rows remain explicitly unknown, while an explicit null expiry means no expiry. The service count remains authoritative when its detail list is capped. The list follows refreshed quota and the existing UI clock without extra requests, and closes when account scope changes.

Pace is remaining quota percentage divided by remaining time percentage, multiplied by 100. Values below 85% indicate faster consumption; above 115% indicate spare capacity. The value is capped at 1000%; stale/expired windows have no live pace. The curve is isolated by hashed account/workspace identity and service reset date. A reset starts a new seven-day cycle. Expiry markers are only for available banked resets that expire inside that cycle; they do not redefine its start/end.

The Codex primary TPS value is settled response throughput: authoritative output tokens for one request divided by the observed window from turn start, previous request accounting or the last required tool result to the last generated item. `token_usage_record.usage.output_tokens` has priority; runtime `last.outputTokens` supplies an earlier settlement when output timing is known. Output includes reasoning once; input/cached input are excluded. Request IDs deduplicate accounting within a turn. A cached snapshot, unchanged counter, unknown start, gap or another turn cannot establish a response window. Missing exact records fall back to the older cumulative-counter estimate. Confirmed blocking-tool time does not count, and a background tool finishing during model generation cannot reset its response window. This is observed response throughput, including first-output latency; it is not model-side decoder speed. Claude numeric request spans carry their own start/end and reported TTFT; they preserve their measurement timestamp and exclude input/cache tokens. Provider totals use the available model-native output counts and are not a tokenizer-normalized model benchmark.

An outgoing model window remains pending through tool execution until its usage arrives. Runtime tool events can close a window backed by model output, but cannot create model-output evidence: several inner tools in one `exec` therefore cannot turn their execution gap into a new request duration. Tool-only attachments and multiple unpaired response windows keep the previous displayed measurement until a confirmed boundary provides usable timing. Nearby authoritative request-log corrections take precedence over runtime estimates in both accounting and the retained display cache, including after source replacement; the original measurement timestamp remains the freshness anchor.

Each task displays the latest settled TPS and observed first-output latency (TTFT proxy), also on its retained completion card. The latency starts at a newly observed turn and ends at the first received nonempty model or reasoning text. Presence and timestamps are retained, never text. A mid-turn attachment cannot infer an unseen first output. A complete log window can recover first-output timing from the matching model-item event (agent-message start or published reasoning completion); timestamps and text-presence only are retained. Partial windows never guess an unseen first output. Numeric service-reported `time_to_first_token_ms` fills remaining gaps from the matching completion log without replaying lifecycle or notifications. First-output timing is cached independently of response throughput and retained across partial reads, duplicate starts, reconnects and source replacement within the same turn; only a confirmed new turn clears it. Queue, network and client delivery contribute to this observation; model-side first-token timing is unavailable. First text bypasses presentation batching; later text timestamps survive coalescing. Final item/usage events precede completion even in one atomic Desktop patch. Late numeric accounting can enrich the same host/thread/turn card without creating activity, replaying a reminder, extending expiry or reviving a dismissed card.

The collapsed header shows global total TPS by adding the available rates of all observed running chats, including both settled-request and legacy estimates. Tool waits retain the chat's last measured TPS rather than imposing a displayed zero; waiting-for-input, ended and internal-review agents are excluded from the active total. Task rows group the parent with its observed running descendants and sum their available rates once. Unmeasured tasks are omitted and make the number partial. A fresh number becomes gray after 15 seconds; the latest measured response remains visible through sparse reports, without a polling timer. New turns clear accounting/latency baselines independently of the displayed TPS cache. An absent/new/old measurement retains the same chat's last measured rate without a marker; missing first-ever measurements remain unavailable. Freshness depends only on the latest contributing measurement timestamp: white until 15 seconds, gray afterwards, even during tools or new turns. Partial or legacy estimates do not change this color rule. Tool waits and cached values cannot refresh the original measurement timestamp or contaminate the next request's token baseline. Legacy cumulative estimates retain their original per-turn baselines, duplicate/reset protection and active-duration limit of 120 seconds.

Spawned-agent relationships come from validated parentThreadId/source metadata and session headers/index metadata. Desktop subAgentActivity IDs and status breadcrumbs, and runtime collab receiver IDs, trigger bounded discovery. Headless agents that cannot supply a Desktop snapshot use the existing incremental log path for numeric accounting; explicit parent status evidence ends their stale log activity and permits later reactivation. Forked logs can embed ancestor headers/history: the cursor keeps its own thread identity and skips conflicting history until an explicitly owned event, including the numeric-only thread-settings boundary, resumes its data. Only IDs and enum statuses are retained, never prompts, messages, paths or nicknames from collaboration items. Task rows and task counts use one root per host; nested agents join the same root, reviews are excluded, cycles are bounded, and missing measurements make the total approximate. No additional polling timer is introduced. A read-only `--diagnose-task --thread-id UUID` reports numeric grouping/rate status without task text or account data.

Local request logs use at most 32 vnode file watches plus four discovery-directory watches. Append refreshes read known cursors only; they do not enumerate sessions or query SQLite. Normal discovery keeps its existing intervals and fallback budget. SSH uses runtime-provided, validated rollout paths beneath the Codex sessions directory, at most 64 cursors/watches, and Linux inotify. It keeps ended paths for 30 seconds to collect delayed usage; missing notifications use bounded file-stat checks. Reads are capped at 512 KiB on attachment and 128 KiB on append, with sanitized frames of at most 512 records. No text, tool output or task input leaves the host.

Ordinary event and incremental-log updates coalesce automatically at five seconds collapsed and one second expanded. There is no refresh preference; saved choices from earlier development builds are ignored and removed on the next Settings save. Expansion flushes pending native/helper events and reads known log cursors immediately, without rediscovery, reconnecting or clearing task cards. First output, turn start/end, tool start/end and attention bypass the batch interval. Original event timestamps and accounting precision are preserved. A busy event queue flushes at 512 entries instead of reconnecting during the longer window. Idle collectors block on events and do not poll at the display frequency; quota/discovery intervals remain independent. See [2.3.0 performance evaluation](performance-2.3.0.md) for the initial candidate measurements and their limits.

The seven-day quota curve keeps its first actual reading and the latest reading in each five-minute interval, including a live endpoint. A window retains at most 2,018 points; older fine-grained caches compact in memory when loaded. Quota refresh remains 30 seconds expanded or 120 seconds collapsed. Successful readings update memory immediately; cache writes coalesce to thirty minutes. First readings, account/home changes and new quota cycles commit immediately. Sleep, source changes and graceful exit flush pending data. An abnormal exit may lose up to thirty minutes of local curve updates; it never alters service quota or task state. Cache loading does not write back merely because it pruned history.

Local Desktop IPC and remote app-server subscriptions project only lifecycle, timestamps, bounded display metadata and output counters. Prompt text, reasoning, tool arguments/output and authentication data are excluded. One startup log scan fills gaps; fallback scans run every 120 seconds while connected or 60 seconds while disconnected. Stream-evidenced threads are skipped. The visible clock updates do not trigger frequent log scans.

The Desktop IPC collector runs natively inside the Swift process on a utility queue. A bounded JSON view validates skipped data without constructing transcript objects. It preserves revision/owner checks and array index mappings, keeps historical turn headers with sparse item counts, and retains item metadata only for the current turn. Patches copy changed containers atomically. Desktop routing and lifecycle changes send bounded discovery hints to the existing SSH helper. SSH runtime metadata and events remain authoritative for SSH activity; cached Desktop views are used for discovery/attention, not SSH running or completed states. The local app-server-control compatibility path and independent SSH fallback continue to use the bounded Python adapter; the usual Desktop IPC path has no local Python child.

Remote Control (`remote-control:`) uses the Desktop owner's versioned stream for lifecycle, output counters, attention and agent grouping. Saved project, membership, pinned-thread and added-environment IDs discover at most eight hosts, prioritizing the selected host, without reading client enrollment credentials. Monitoring is enabled by default and can be disabled independently of SSH. New running attachments require a resumed stream with active runtime status; stale idle/unloaded/error snapshots do not create activity. An already observed turn survives an idle-only patch until explicit terminal evidence arrives, so separately delivered final usage and completion are preserved. Owner disconnection, resume loss and revision gaps invalidate activity without inventing completion. Reattachment restores metadata, stage and agent relationships, seeds cached usage and cannot infer unseen first output. Codex must remain open and connected, with the conversation loaded by a stream owner; this path has no independent remote-host discovery or log fallback. Desktop owner connectivity does not independently prove remote network health. SSH continues to use its existing helper as runtime authority. Each host retains separate task and token-rate state.

Cached counters reseed the legacy rate baseline without producing a measurement or refreshing the retained display timestamp. A changed cached counter also invalidates an incomplete runtime response window. Separately patched cumulative and last-request counters are baseline-only until coherent accounting is observed; an older request's last count cannot be paired with a newer cumulative total. Remote Control retains at most 64 completed-turn metric states per host for delayed coherent usage, subject to the existing 30-second observed-output timing bound. These updates enrich only matching retained cards without creating activity, replaying completion, extending expiry or restoring a dismissed card. Pending input/approval is not considered resolved by owner disconnection; cached attention can remain until a replacement snapshot or an explicit resolution boundary arrives.

The inherited cumulative-counter fallback remains approximate when attaching mid-request. Its first live increment can include output generated before attachment, while the measured interval begins at the cached baseline's receipt. A fresh report therefore does not prove a fully observed request window and can produce an inflated estimate. Remote Control has no independent request-log correction for this case; preserving upstream's fallback policy does not eliminate every possible TPS spike.

Ephemeral conversations are excluded before projecting activity or input/approval requests. A snapshot or later patch marking a conversation ephemeral clears its pending reminder and releases only that conversation's interest; ordinary conversations on the same host remain monitored. Remote runtime discovery also excludes ephemeral threads before attachment. `thread/name/updated` updates the existing task's bounded display name without changing its lifecycle or token-rate baseline and without a new RPC while attached. Name metadata also reaches retained completion cards after their runtime subscription is released, including automatic naming that finishes after the first turn. These updates use the existing bounded metadata discovery cache and cannot create a task, replay a reminder, extend retention or resurrect a dismissed card. A stream without a name can retain the same host/thread's known log title; blank/incomplete RPC metadata does not erase it. An explicit name removal prevents the older cached name from returning.

Desktop `requests` and current-turn agent-message `questions` are observed for local, Remote Control and enabled SSH host IDs, independently of backend runtime subscriptions. Only hashed identifiers, routing, question-presence markers and input/approval kind are retained; question text/options and reply content are skipped. Nonblocking questions produce a persistent attention badge without changing a running task to waiting. Opening a chat does not resolve a question. Server requests clear when explicitly removed. Message questions clear on removal, a later ordinary or steering user message, or the turn ending. Desktop-only dismissal/timeout UI state is not in this stream, so a dismissed message question can remain indicated until one of those observable boundaries. These events bypass the selected performance-update batch and are not throttled by curve persistence. System notifications retain the user's existing enable/disable preference. The collapsed header prioritizes pending input, unread completion, then the latest updated running task. Native state symbols match the approved design; a single running task displays its current stage, while multiple tasks retain task units (99+ maximum). Reply/approval wording remains explicit. Notch mode reserves the real camera gap and equal wings for visible components, abbreviates large rates with k/M and hides unmeasured-rate dashes. Long English attention text takes precedence over rate in the default Notch layout; hiding status text allows a chosen TPS component to remain visible. Pending attention joins its matching task row without changing a running phase; requests whose runtime task is not yet available retain a routing row in the same paginated task region. Low/exhausted quota markers default to the right, independently of task tint, and can be moved or hidden in the component editor. Standalone connection/unknown status banners are omitted from the island; connection diagnostics remain in Settings. Explicit failed endings retain a failure marker within the existing interrupted terminal lifecycle and clear it on the next turn.

Completed streams release their active runtime slots after delivering their terminal state. Desktop interests retain at most 64 dormant revision/header projections per host, with zero retained terminal items, so an already-open conversation can publish its next turn without waiting for fallback discovery. Native frames reach the monitor through a bounded ordered queue and enter the UI in the same order, including final events flushed before EOF. Trailing token/status patches do not rehydrate completed items or discard queued completions; a rejected patch first delivers earlier valid events before invalidation. Whole snapshots and item-list replacements restore the latest model stage even without an individual text delta. The completion inbox retains cards independently and rejects older log replay; idle status alone cannot finish a turn. Covered log baselines remain available for reconnects without spending the fallback-discovery budget. Missing/unreadable logs become unconfirmed rather than staying running indefinitely.

Large sanitized fallback snapshots use ordered parts of at most 1 MiB and commit only when the final part arrives. The pipe reader pauses between consumed chunks to apply backpressure; incomplete snapshots keep the previous fallback intact. Only Pacer-owned subscriptions and transport state are released.

Task discovery combines versioned following/read-state announcements with filesystem notifications on both the routing file and Codex home directory. A fingerprint avoids rereading unchanged state; changed `.codex-global-state.json` files contribute only allowed host/thread routing IDs. Startup hints are bounded to eight per host; subsequent new IDs trigger subscriptions independently. In-place writes and atomic replacements are both observed; a replacement reopens the file watch. The socket and filesystem descriptors share a kqueue wait, so discovery wakes immediately without a periodic log scan. Routing metadata never creates a running/completed state by itself. A follow is not considered hydrated until a valid snapshot/patch arrives: missing snapshots retry after 0.5, 1 and 2 seconds, then expire after a final five-second wait. Existing interests also answer owner following-status requests, including after reconnects. Orphan hints release their slots. SSH hints travel through the owned helper stdin and trigger bounded metadata reads immediately. Remote index changes independently trigger loaded-list discovery even without a Desktop announcement. Linux helpers watch only state SQLite/WAL file notifications with inotify; other platforms or unavailable watches compare file metadata every two seconds. No database contents are read by this watcher. Index-triggered RPCs coalesce at one-second-or-longer intervals, with two bounded rechecks for an index write that precedes runtime activation. The one-minute loaded-list safety poll and uncovered-log scan intervals remain separate. A confirmed active runtime read displays a quiet running task before item events; its rate remains partial. When the first item supplies the turn ID, the state adopts that ID without resetting the confirmed-start evidence or partial-rate baseline. Older completed logs therefore cannot hide the new turn. Confirmed idle metadata suppresses older running log replay without inventing a completion. Only explicit terminal evidence creates a completion, including when active and terminal evidence arrive in the same batch.

Desktop IPC is private and version dependent. Sender identity, protocol/version and consecutive revisions are checked; gaps request a new snapshot with bounded retries. Unsupported sessions fall back to sanitized logs. Silence and orphan terminals cannot end an active turn. Connection success does not prove every client is observed.

The SSH helper supports Python 3.6 and newer. Log timestamps use a shared parser for UTC, numeric offsets and fractional seconds, without `datetime.fromisoformat`. Log-scan deadlines advance before reading: a failed scan retries at the existing cadence without disconnecting a healthy runtime or blocking its 15-second status heartbeat. Other recurring helper errors wait at least one second, report disconnected status on the heartbeat cadence and remain interruptible by stdin EOF. No additional healthy-state polling is introduced.

SSH uses enabled discovered aliases, known host keys and existing non-interactive authentication. Agent/port forwarding are disabled. Pacer never modifies or restarts shared Codex processes. Source changes, sleep and quit close only Pacer-owned helpers; stdin EOF and broken stdout end remote helpers. Keep real subprocess lifecycle tests when changing shutdown behavior.

Loaded-runtime discovery requests pages of 64 IDs with at most eight metadata reads in flight. Idle and review threads do not consume the 32 active subscription slots. Outstanding reads reserve capacity; queued candidates continue as slots are freed rather than restarting from the first page. The candidate queue is capped at 128 IDs and cursor cycles are rejected. This changes discovery coverage, not the established scan intervals or curve-write schedule. Valid queued runtime events flush before EOF, reconnect invalidation and normal helper exit.

Canonical activity IDs recognize their UUID suffix before treating a rollout path as a file, so dotted SSH aliases remain valid without fallback metadata. Live activity rejects events for the last 64 retired turn IDs while preserving attachment to an ongoing turn after reconnect. A runtime `systemError` remains unconfirmed ahead of older running log data until fresh evidence arrives. Once a terminal state has been published and reclaimed, the confirmed-idle marker rejects later unload/error messages so they cannot recreate an unknown task and clear its completion card; a confirmed new turn removes that marker. The completion inbox independently rejects unknown transport states without evidence of a newer turn, including after that bounded marker is evicted or a source is recreated. Desktop turn selection uses known unequal start times, active state when timestamps are absent/equal, and the observed current turn to preserve its ending. The same selection rule controls item hydration. Both collaboration-tool type names map to one blocking-tool state. Completion notifications accept a confirmed live start and ending in one publication, deduplicate by thread/turn, and remain quiet for historical startup logs. Notification permission and the user's enable/disable preference still apply.

## Persistence and verification

The production bundle is `com.codexpacer.app`. A one-time allowlist migration copies unset native preview preferences; existing production choices take precedence. `~/Library/Application Support/CodexPacerIsland` remains the cache/lock location for continuity. Completed cards and unread reminders are in memory; startup history does not replay old alerts. Successful verified conversation opens persist up to 512 acknowledgment hashes in an atomic, owner-only file, so the same ending stays dismissed after normal relaunch. Opening a terminal parent also acknowledges only eligible descendant endings captured at that click: the child and its bounded ancestor chain must already be terminal, share the provider/host/source and still match their captured turn, start and ending states after the asynchronous open returns. Running descendants, late endings, new turns, changed parent relationships and replaced sources remain untouched. The hashes distinguish providers, local homes, configured host homes, sessions, explicit turns and ending states; legacy turns without an ID also include normalized start/end times. No path, account or task text is stored. Corrupt or unsupported files are ignored. Expiry, source removal, failed opens and Terminal handoffs do not write acknowledgments.

After presentation changes, reproduce the changed interaction in the actual app and check its affected layout. Exercise anchors/reversal for geometry changes, persistence for settings changes, expiry hover/tap for expiry changes, and quit controls for shutdown changes. Do not rerun unrelated presentation or updater matrices. Check reduced motion/transparency and older macOS when those behaviors change. Source tests do not establish live appearance, protected Codex deep-link behavior or every OS/display configuration.

Settings reuses its native window and geometry but releases its hosting content on Save, Cancel, the red close control or Command-W. Reopening constructs a fresh draft from saved preferences rather than retaining hidden history charts and model-observing views. This changes view lifetime, not collection cadence, and does not establish a measured overall energy reduction.

Settings retain the saved quota-window choice while quota is unavailable and validate it after usable data returns. Conversation navigation uses the same application locations as CLI discovery; a failed open preserves the card and its unread reminder, and reports the failure separately from quota errors.

Island width defaults to Adaptive for new installations and upgrades from earlier releases, in Automatic, Notch and Floating modes. Existing display/appearance choices remain intact; a subsequently saved Specified Width choice persists across launches. The header measures its unconstrained visible component row; a real notch reserves equal wings around the camera. Without a camera gap, including Notch mode on an external display, the default header uses each side's natural width so token-rate text cannot force the status into an unnecessarily narrow equal half. Expanded task rows supply an independent preferred width, bounded at 680 pt with a 440 pt minimum. Specified mode uses one shared width for collapsed and expanded states, controlled by a live preview and one slider without numeric width fields. The internal width range is 360–900 points. A saved width from the earlier local two-field build is migrated on load, and obsolete keys are removed on save. Hardware-notch clearance and the selected display's edges constrain both modes. Width changes use the existing top-anchored, centered and quantized spring, and content height is measured again at the resulting width. Settings apply on Save.

The collapsed bar has one configurable row, persisted as schema 3 in `compactIslandLayout`. Both Notch and Floating modes use only left and right lanes. Schema 1 center components migrate into the left lane after its existing components, retaining known choices and deduplicating across both lanes without writing during load. Settings edit a draft with task, performance, quota and warning categories, direct visibility toggles and measured local drag hit regions for insertion or side changes. The editor's Save runs the enclosing Settings validation and applies layout and pending settings once; Cancel discards its draft. Defaults retain the status/rate/quota layout with a numeric task badge. Unknown component names are ignored; malformed or unsupported schemas use the standard layout. Removed subagent-count and action components are discarded during legacy migration; the old quota-window, reset countdown and warning choices map to the quota/pace label, time-remaining percentage and conditional warning components. Unchanged factory layouts enable the numeric task badge and new conditional SSH warning; custom and intentionally empty layouts preserve their choices. The model caches the decoded layout until Settings save. The real header and both previews share the same renderer. Its unconstrained whole-row measurement drives adaptive width and can shrink after hiding components; fixed width still uses the existing single slider. A real camera gap stays centered between the two sides. The expanded panel and all collection, timing and freshness policies are unchanged. An intentionally empty bar remains hoverable and has a Settings/Quit context menu, with the existing expanded footer and application shortcuts available. Task count uses a numeric badge. The quota/pace percentage and label follow the existing compact-metric selection, and time remaining shows its percentage of the quota window. Low-quota, delayed-update and SSH-disconnected indicators appear only while their condition is present; SSH monitoring disabled means no SSH warning. Collapsed TTFT keeps the latest measurement across all non-review sessions/agents, selected by its original first-output timestamp rather than turn start or later tool events, and remains visible through new turns, completion and card removal. Source changes reset this in-memory value. No refresh timer or collector is added.

Keep tests grouped by the behavior they protect. When consolidating overlapping scenarios, preserve distinct input paths and boundary assertions, especially account isolation, sanitized transport, real helper shutdown and window rounding. Avoid fixed test counts or catalog-size thresholds as acceptance criteria.

## Performance checks

The event benchmark compares the embedded Desktop IPC projection from two source trees with identical synthetic patches. It checks projected state and emitted events for equivalence, excluding wall-clock timestamps, and alternates execution order. To compare an uncommitted change against the current commit:

```sh
task_baseline="$(mktemp -d /private/tmp/pacer-baseline.XXXXXX)"
git archive HEAD native | tar -x -C "$task_baseline"
python3 scripts/performance/benchmark-events.py \
  --baseline "$task_baseline" --candidate . \
  --output output/performance/events.json
```

Use the intended baseline ref instead of `HEAD` for committed changes. Results measure component CPU cost, not whole-app speed, memory, energy or SSH I/O. Keep raw results under ignored `output/`; profile the current packaged app for UI measurements. The [2.3.1 energy comparison](performance-2.3.1.md) covers calibrated CPU accounting, collapsed/expanded presentation checks, subagent traffic and installed collectors. [Historical measurements and their replay harness](https://github.com/RyanZhangNTU/codex-pacer/blob/v2.1.3/docs/performance.md) remain in tagged source, but that UI harness predates the current app packaging and is no longer maintained.

Live UI measurements need a verified candidate PID, current unlocked-machine state and fresh main-panel checks at the interval boundaries. Unknown lock timing or potentially stale UI frames leave a window UI-unconfirmed and exclude it from visible collapsed/expanded comparisons. Record active task/source changes and concurrent windows; an active run is not isolated idle. Per-process CPU and short-window OS energy counters apply only to their captured process set, with partial descendant coverage during reconnects; they do not measure WindowServer, GPU, remote helpers or whole-system power.

For explicitly authorized local troubleshooting, set the production preference `pacerLocalRuntimeTrace` to true before launch. The Mac process writes at most 1 MiB to a private `/private/tmp/pacer-runtime-trace-PID.jsonl` file containing hashed routing identifiers, lifecycle methods, phases and timestamps. It excludes task text, paths, requests and token values, and adds no remote diagnostic code. Delete the preference and relaunch after diagnosis. Normal launches do not create or write this trace.
