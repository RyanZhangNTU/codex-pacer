# Windows 显示器与全屏策略

Appearance 页提供“主显示器”和各个具体显示器，以及“在全屏应用上方显示”开关。主显示器跟随系统设置，与 Mac 缺省 `displayID=0` 的落点一致。全屏开关缺省关闭，与 Mac 的 `showInFullscreen` 一致。

## 选择与保存

Windows 的 `displayID` 保存显示器设备接口路径，另存名称和选择时的位置作后备。匹配先查设备路径，再查唯一的名称与位置组合，不依赖易变的 DISPLAY1/2 编号。路径来自 [EnumDisplayDevicesW 的设备接口查询](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaydevicesw)。同名、同位置仍有歧义时回退主屏。

选中的屏幕断开后，岛暂时移到主屏，Settings 保留断开的选择并说明回退；重连后恢复。主屏变化影响“主显示器”选项，指定设备保持原选择。系统暂时无法枚举时使用当前 HWND 的屏幕信息，保留偏好，等待显示事件或再次打开选择器刷新。

这些字段通过现有 Windows preferences-v1.json 的 schema 2 保存。`showInFullscreen` 使用 Mac 布尔键；`displayID` 缺省、null、空字符串或数字/字符串 0 都表示“主显示器”，具体设备使用 Windows 设备路径字符串。旧 `displaySelection` 的 automatic 和 primary 都显示为“主显示器”；读取、打开设置和刷新显示器列表不改写旧值。schema 1 只在成功编辑后迁移。名称和物理位置另存作后备，设备选择不进入引擎配置，不触发采集器重启。详见[偏好对应关系](windows-preferences.md)。Mac 的偏好键、保存格式与运行路径不变。

## DPI 与窗口定位

显示器目录提供物理桌面矩形和工作区。窗口先移入目标屏，再沿用当前 HWND 的实际 DPI 与共享 Swift 布局，把物理坐标转换为逻辑点。切屏和 DPI 变化直接重建静止布局，避免拿旧 DPI 的坐标跑弹簧，也不保留横跨两个屏幕的透明画布。Notch 使用目标屏顶部中心；Custom 使用目标屏工作区，保留任务栏边距和展开方向。

拓扑、工作区和 DPI 更新由系统事件或窗口消息驱动，不轮询。隐藏时也处理这些变化。应用及展示测试使用 PerMonitorV2；[Windows 的 DPI 说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow)解释了 HWND 与所在显示器 DPI 的关系。

## 全屏行为

关闭开关时，目标屏存在全屏应用就隐藏岛，退出、最小化或改为普通窗口后恢复。开启时，岛保持在目标屏全屏应用上方。恢复只针对策略隐藏；用户主动隐藏或关闭的岛不会被自动打开。逻辑展开状态和数据刷新不因全屏隐藏而改变。

检测复用遮挡观察器和 250 ms 尾随节流，区分“全屏应用存在”与“岛确实被完整遮挡”。前者在岛隐藏后仍继续检测，避免反复显隐；后者继续用于暂停装饰动画。客户端矩形需覆盖目标屏，排除最小化、其他虚拟桌面、桌面/任务栏、分层窗口、工具窗口和 Pacer 自己的窗口。分层窗口的透明度不能仅由矩形证明，因此保守排除；使用此类样式的实际全屏应用仍需验收。普通带标题栏的最大化窗口不算全屏。独立 Composition 应用可按客户端几何识别为全屏，其未知透明度仍不能用于宣称完全遮挡。

提升只在需要时使用 [SetWindowPos 的 NOACTIVATE 标志](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)，随后同步玻璃背景的位置；不调用前台激活，也不更改非岛区域的输入形状。若事件密集，仍只保留一个待处理刷新，最终状态会重新计算。实际生效时间还取决于 UI 调度，不能把 250 ms 当作繁忙系统上的硬期限。

## 验证范围

定向 Desktop 测试覆盖设备路径优先、名称与位置后备、歧义、主屏变化、断开重连、持久化、失败回滚及不重启采集器。保存后启动新进程，分别读回具体设备和两种旧主屏值，检查显示器、全屏及无关字段保留，读取前后文件字节一致。共享布局检查有 320 次调用，覆盖负坐标、工作区、各锚点、收起/展开、Notch/Custom 及 100%、125%、150%、200% 的换算。

`scripts/windows/test-presentation.ps1 -Configuration Release -Group display` 使用独立进程的合成不透明全屏窗口，检查两种材质的开关、全部表面层级、非激活、岛外命中、持续隐藏、最小化/退出恢复和用户主动关闭。注入的左右屏拓扑在同一真实屏幕内验证实际窗口移动、断开重连、分辨率变化和仅按目标屏判断全屏。设置检查覆盖中英文、浅深色、保存和失败回滚。夹具不读任务内容，退出时关闭自己的窗口和子进程。

`-Group displaySettings` 只运行显示器设置检查，覆盖唯一的“主显示器”选项、两种旧值读取、打开设置及拓扑刷新不保存、失败回滚、重连和全屏开关。

审查后的定向复验通过：显示器与全屏逻辑、新进程读回、中英文 × 浅深色四组显示器设置检查。Release 编译警告为 0，测试窗口已关闭。

2026-11-03 本机仅一块屏幕、150% 缩放。基于 `03c98cb` 接入 schema 2 后，相关展示组跑一轮通过，Classic/Liquid Glass 两种外观偏好下均通过全屏隐藏、恢复、全部表面层级、非激活和岛外命中；全部测试窗口与子进程已关闭。显示器与偏好持久化定向检查、940 项完整引擎/共享测试及 Release 构建通过，编译警告为 0。147 个 Core 文件与 EngineSupport 独立编译通过，Core 对 Windows 宿主类型的反向引用被拒绝。窗口结果见[数值记录](performance/windows-display-fullscreen.json)，不把注入拓扑当作真实多屏验收。原有遮挡、动画、输入与设置断言保留；原先 display/fullscreen 控件禁用的预期改为新功能可用。按提速规则，没有在本机重跑完整展示矩阵、打包、安装或 CPU 采样。

## 待用户 Windows 实机验收

- 真实多屏连接、断开、重连与主屏变化，含同型号显示器和接口变化。
- 多屏混合 DPI、缩放/分辨率调整、不同任务栏位置，以及退出重开后的实际落点。
- 实际浏览器、视频和游戏的 borderless / exclusive 全屏、跨屏全屏及系统特殊桌面。当前合成窗口验证不能证明这些应用的全部行为；遇到限制需保留复现证据再决定方案。

同型号设备交换位置且接口标识也变化时，名称与位置后备无法证明物理设备身份。此时用户应重新选择显示器。没有修改 Windows 显示或无障碍设置，无需恢复系统设置。
