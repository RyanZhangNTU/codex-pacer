## 如何复现

默认只做被动监听：

~~~sh
python3 scripts/native/probe-local-events.py --seconds 20
~~~

订阅桌面端已经广播的本机会话流：

~~~sh
python3 scripts/native/probe-local-events.py --follow-local --seconds 30
~~~

可以重复传入 `--thread UUID`，将订阅限定到指定会话。探针只跟随收到的本机通知，最多订阅四个流，不把订阅数当作运行任务数。单次观察限制为 5–60 秒，单帧上限 16 MiB，总接收量上限 128 MiB；超过数据限制或无法解析消息时结束诊断，未识别版本的状态消息忽略。长会话的快照可能超过单帧上限。

探针验证 socket 和父目录属于当前用户、权限没有向其他用户开放。它只发送初始化、跟随/取消跟随通知，以及拒绝路由请求的回复；不调用任务启动、恢复、中断、审批或输入接口。退出时取消跟随并关闭连接，不启动或重启 Codex 服务。

输出仅含已知事件类型、状态枚举、item 类型、输出 token 计数、数据量及探针 CPU 时间。会话 UUID、路径、标题、提示词、推理正文、工具参数和结果不会输出。autoreview 来源被识别后取消跟随；用户轮次内部的 `automaticApprovalReview` item 不计入工具类型。首次识别来源仍可能需要接收一次快照。

`snapshotItemTypes` 是当前轮次快照中的 item 组成，包含此前已经执行的 item；`patchItemTypes` 才来自此次观察期间的更新。`eventLoopIterations` 包含读取大帧的多次循环，不能作为操作系统 CPU 唤醒次数。

## 接入新版 Pacer 的路线

优先使用已有官方 app-server 控制端点。本机没有该端点时，可在实验开关下尝试桌面 IPC，保留当前文件监听。官方文档说明了 [app-server 的 stdio、Unix socket 与 WebSocket 协议](https://learn.chatgpt.com/docs/app-server#protocol)，此次桌面 IPC 的消息版本则来自当前安装包和实际握手，兼容性需要单独维护。

正式接入前需要完成以下验证：

1. 从已有任务索引选择正在运行的用户会话，先排除 autoreview。只保留当前轮次、item 类型与状态、时间和输出计数，不保留历史正文。
2. 检查消息来源、轮次和增量版本连续性。版本缺口、任务切换、断线或应用升级时交回日志采集；同一轮的明确结束状态才触发“本轮结束”。
3. 用实际生成和工具调用对照 token 计数更新时间；确认同步等待与后台计算的区别，再接入现有吞吐估算。
4. 保持连接，避免反复拉取完整快照。测量首次快照、持续生成和空闲三个阶段的 CPU、真实唤醒和内存，并检查跟随者是否影响桌面端卸载闲置会话。

目前探针按已验证的状态消息版本 `11` 读取；遇到其他版本不会将消息作为状态证据。完整的增量版本连续性和任务阶段重建属于后续适配器的工作，此次诊断没有实现。
