# 本机与 SSH 实时订阅

新版默认使用订阅更新任务。开发基准为 `codex/collapsed-rate` 的 `e7381d4`，本次在 `codex/subscription-updates` 开发；没有创建 PR。

## 当前方式

本机连接现有 app-server 控制端点；没有该端点时连接 Codex Desktop 的本机 IPC。SSH 连接已配置主机的 app-server Unix WebSocket。每个来源保持一个 helper 连接，不启动或重启共享服务，不发送模型输入。

本机已移除文件变化监听，SSH helper 也不再使用 inotify。日志仅在启动时补全，以及正常连接下每 120 秒发现未覆盖会话、断线时每 60 秒兜底。已由事件确认的运行会话跳过对应日志读取。订阅之外的独立 CLI 会话仍需要这种低频补充，不能宣称所有任务都由事件流覆盖。

折叠时钟每 30 秒更新，展开时每两秒更新可见时间；任务事件会直接更新界面。这些时钟不再触发频繁日志扫描。额度保留原有刷新节奏，因为账户可能包含其他设备的使用。

设置只显示订阅连接情况，不再提供恢复两秒日志轮询的实验开关。

## 状态与吞吐

本机适配器丢弃正文，只保留来源、会话与轮次标识、item 类型和状态、时间、输出计数及显示名称。当前轮次中 autoreview 的 item 不改变生成或工具状态；独立 review 来源排除。

桌面 IPC 使用消息版本 `11`。每个流校验发送者和连续增量版本，批量更新全部有效后才接受状态。缺口撤回该流的状态，再请求快照，重试间隔至少 30 秒。协议不兼容或连接失效时由日志补充。只有已观察当前轮次的明确结束状态才显示“本轮结束”，idle 状态和工具结束不能结束整个轮次。

首次快照可能包含较长会话历史。原始正文只在解析时存在，随后丢弃；适配器保留最小状态投影，单帧限制为 16 MiB。保持连接可以避免频繁接收完整快照。桌面 IPC 属于内部协议，后续版本需要验证兼容性。

速度使用服务上报的输出 token 增量，除以扣除已确认工具阻塞后的采样时间。并行等待区间取并集。后台工具仍运行时，模型生成信号会恢复计算。文本 delta 只提供生成信号，不按字符数或事件条数换算 token；思考 token 已包含在输出计数中。

中途接入当前轮次时先建立计数基线，不把此前生成的 token 除以接入后的短时间。已知估算在采样停顿时保留为灰色；首次采样前，折叠时隐藏速度及单位，展开时显示“采样中”。网络、请求准备和计数上报延迟仍可能影响分母，因此它是生成阶段的平均吞吐估算。

事件按 250 毫秒合并，远程传输丢弃正文、推理内容、工具参数及结果、认证数据和输入计数。[官方事件接口](https://learn.chatgpt.com/docs/app-server#events)与[输出计数说明](https://developers.openai.com/api/docs/guides/token-counting#understand-output-token-counts)提供官方通路和计数口径；桌面 IPC 的验证另见[本机探索记录](local-event-exploration.md)。

## 验证记录

2026-10-02，使用原生诊断程序观察现有服务 20 秒：

| 来源 | 已连接 | 订阅运行会话 | 文件监听 | 日志扫描 |
| --- | --- | ---: | --- | ---: |
| 本机 | 是 | 1 | 关闭 | 0 |
| RTX PRO 6000 | 是 | 1 | 关闭 | 1 |
| RTX 4090 | 是 | 0 | 关闭 | 1 |
| A100 | 是 | 0 | 关闭 | 1 |

实际收到本机和 SSH 两个任务的事件证据，诊断中内部 review 数为 0。SSH 的一次扫描是启动补全；本机启动日志补全由原生模型单独完成，不包含在 helper 的扫描计数中。不能把候选日志记录数当作运行任务数。

本机 helper 累计 CPU 时间为 0.158329 秒，包含启动、快照解析与更新；各 SSH helper 为 0.035845–0.082256 秒。这次短测没有测量电量或功耗，也未证明长期节能幅度。事件循环迭代数不能替代真实 CPU 唤醒次数。

`npm run island:test` 的 96 项测试通过，覆盖实际模拟 Unix socket、消息分片、只接受观察者操作、版本缺口、正文过滤、中途接入计数、工具等待、订阅覆盖时跳过日志和兜底恢复。测试不修改真实任务，也不运行模型。采集循环的模拟时钟测试验证正常连接时两分钟补全、无连接时一分钟兜底；最终原生 Release 构建与隔离目录签名通过；iCloud 副本清除重新附加的 FinderInfo 后，严格签名校验通过。实际预览显示 4 个连接来源和 2 个订阅运行会话，同时展示本机与 SSH 两个任务。

## 复现

~~~sh
npm run island:test
npm run island:build
"output/island-preview/Codex Pacer Island.app/Contents/MacOS/CodexPacerIsland" --diagnose-events --observe-seconds 20
~~~

诊断只输出状态与计数，不输出会话正文或账户认证数据。应用退出和睡眠时只关闭自己的 helper 和 SSH 连接；唤醒后重新订阅。

## 早期实验

原稳定版本保留在 `codex/pacer-island` 的 `b83f8f6`。早期订阅实验为 `codex/realtime-events` 的 `07ff381`，当时本机仍使用文件监听，SSH 使用事件与文件监听混合采集。

早期在 RTX PRO 6000 的一次 20 秒空闲对照中，两秒扫描为 10 次，混合采集为 1 次；累计 helper CPU 分别为 0.037114 和 0.035276 秒。该结果只验证扫描减少，不能推算电池续航。当前实现已移除文件监听，不沿用这个混合方案。
