# 实时事件订阅实验

现有版本保留在 `codex/pacer-island` 的 `b83f8f6`。实验在 `codex/realtime-events` 中开发，不涉及旧版 Tauri 功能，也未进入 PR 流程。

## 开启和关闭

构建并打开原生预览，在设置的“实验”中开启“实时事件订阅”。默认关闭；关闭后恢复原采集方式。

~~~sh
npm run island:test
npm run island:build
open "output/island-preview/Codex Pacer Island.app"
~~~

实验连接已经运行的 app-server 控制端点，不启动共享服务、不创建任务、不发送模型输入。只对已确认 active 的会话调用 `thread/resume` 建立订阅，传入 `excludeTurns: true`，不传配置覆盖。闲置或未加载会话不会被恢复。

本机当前没有可连接的 app-server 端点，因此继续使用文件监听。已配置的 SSH 主机支持 Unix WebSocket。连接成功不等于所有任务都在事件流中，设置分别显示连接数和订阅数。

后续[本机事件订阅探索](local-event-exploration.md)已验证桌面 IPC 能返回现有本机会话的状态与输出计数。这条通路目前仅用于诊断，尚未接入原生采集器。

## 状态与速度

模型生成、工具执行、等待回复和本轮结束分别处理。部分任务尚未建立速度样本时，不会仅因其他任务阻塞而把全局速度显示为 0。任务执行工具时仍计入运行任务数量，但工具阻塞期间的生成速度显示 0。后台工具尚未退出时，若收到模型生成事件，继续计算模型速度。

速度使用服务上报的输出 token 增量，除以采样间隔中扣除工具阻塞后的时间。并行工具的等待区间取并集。文本 delta 只提供生成状态信号，不按字符数或事件条数换算 token。思考 token 已包含在输出总计中，不重复相加。

中途接入一段请求时，先建立计数基线，不把此前生成的 token 除以接入后的短时间。旧流不能覆盖文件中更新的轮次；相同主机和 UUID 的任务只显示一次。断线保留已经确认的结束记录，其他状态由文件采集补充。

网络、排队、请求准备和计数上报延迟仍可能影响分母，因此这个值是生成阶段的平均吞吐估算。[官方事件接口](https://learn.chatgpt.com/docs/app-server#events)和[输出 token 计数说明](https://developers.openai.com/api/docs/guides/token-counting#understand-output-token-counts)说明了可用事件与计数口径。

## 开销控制

事件按 250 毫秒合并。Linux 主机通过文件变化通知补充日志；空闲时每 30 秒发现新会话。文件触发的扫描最多每秒一次，已订阅任务的日志变化不会重复触发扫描。无法使用文件通知或事件流的来源仍按原来的两秒间隔采集。

SQLite 数据库及 WAL、SHM 文件不作为扫描触发源。读取 WAL 数据库本身可能触碰或创建、删除共享文件，监听它们会形成反馈。会话目录存在时，不监听整个 Codex 主目录。

折叠岛的显示时钟由两秒改为 30 秒，任务事件仍直接更新界面。远程 helper 只传回会话名称、标识、阶段、时间和输出计数，丢弃正文、推理内容、工具参数及结果、认证数据和输入计数。

## 验证记录

2026-10-02 对现有 SSH 服务完成实际握手与空闲诊断。初次空闲检查没有已加载任务；随后最终应用在 RTX PRO 6000 上订阅了一个实际运行的用户会话，诊断记录 `attached=1`、`Stream-evidenced tasks: 1`。原生面板同时显示本机与 SSH 两个任务，未重复计数。真实执行事件已经收到，生成阶段的 token/s 数值准确度仍需更长时间对照。

在 RTX PRO 6000 主机的一次 20 秒空闲对照中：

| 方式 | 日志扫描次数 | helper 累计 CPU 时间 |
| --- | ---: | ---: |
| 原两秒扫描 | 10 | 0.037114 秒 |
| 修正后的事件与文件监听 | 1 | 0.035276 秒 |

实验探针记录 11 次事件循环迭代，扫描减少 90%。CPU 数字包含启动和导入开销，单次短测不能据此推算电池续航或功耗改善。生成期间的 CPU 开销和实际电量仍待实测。

`npm run island:test` 的 89 项测试通过，Release 构建和预览签名校验通过。测试使用独立 Unix WebSocket 服务模拟生成、工具、结束事件，覆盖分片帧、握手验证、只订阅 active 会话、autoreview 排除、正文过滤、等待时间计算和断线保留。模拟测试不运行模型，也不修改用户会话。

诊断命令只输出状态和计数：

~~~sh
"output/island-preview/Codex Pacer Island.app/Contents/MacOS/CodexPacerIsland" --diagnose-events --observe-seconds 20
~~~

后续实测需要一个正在运行的 SSH 任务，核对思考、输出、同步工具等待和后台计算阶段。确认阶段切换与吞吐后，再延长空闲和生成测试时间，测量本机 CPU 唤醒与电池开销。
