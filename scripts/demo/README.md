# Native island state approval demo

Build with `python3 scripts/demo/build-state-approval.py`. It copies the current native app into a private temporary workspace, replaces only that copy's entry point, and builds a separately identified app. Shipped sources and `/Applications/Codex Pacer.app` are not modified.

The revised gallery contains 26 synthetic task, attention, quota and mixed-state cases. Four standalone connection/unknown cases were removed following review. Each case displays collapsed Notch and Floating previews using native island views. The proposed Notch width is 480 points with a 180-point camera reservation; Floating remains 300 points. Expanded previews and an English switch are available. The first case restores the explicit “2 个任务” / “2 tasks” label and lets the reviewer switch which task most recently updated. Its icon follows that task's stage.

Thinking uses `brain`, tool execution uses `gearshape.2.fill`, and idle uses `tray`. Attention labels read “待你回复” / “Reply needed” and “待你审批” / “Approval needed”; expanded attention belongs to the corresponding task row instead of a separate request list. Longer English attention labels omit the rate on the Notch rail to remain readable; Floating and expanded task rows retain it. Unmeasured rates have no dash in Notch mode. Low/exhausted quota warnings appear beside the right-hand quota reading, preserving the left task state. Completion does not add a secondary connection icon. The production lifecycle retains explicit failure evidence within its interrupted terminal phase; the approved failure icon and text distinguish it in the UI.

Only the human reviewer should activate “通过本项并继续” or “需要修改”. Preview navigation does not count as approval. Decisions and optional comments are recorded individually in ignored `output/state-approval-2.2.0/approvals.json`; this file does not authorize publication or installation. `build.json` records the app path. No blanket approval button is provided.

The first review's complete feedback is backed up in `feedback-round-1.json`. Schema 3 preserves unaffected approvals and marks previously approved cases with changed icons/layouts as requiring recheck. It writes migrated decisions only when the human submits a decision. Previous comments remain visible until replaced by a new decision. Removed cases no longer count toward the gallery total.

The gallery starts no quota CLI, event collector, SSH connection, updater or system notification. Its preferences, fake home and cache are separate. Language switching is enabled only in the temporary localization copy. Runtime fixtures use the actual projection internally via a temporary helper; task text and quota values are synthetic.

The icon-selection tab offers three native SF Symbol candidates for each of 13 state-icon categories. Each candidate has an enlarged specimen, actual-size Notch and Floating headers, and a native task row when applicable. Only human selection buttons save `icon-selections.json`, separately from state approvals. Unselected categories remain undecided; the first candidate is merely the preview default. Saved choices also apply to the state-review tab, including matching task rows and right-hand quota markers. Shared states in combined cases reuse the same choice. Control icons are outside this state-icon selection round.

This is a design preview, not evidence of production hardware-notch anchoring or animation acceptance. Validate approved changes on the real panel before shipping. Screenshots, approvals and build receipts stay local.
